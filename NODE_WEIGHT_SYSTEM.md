# Система весов узлов и защиты от мошенничества

## Обзор системы

Реализована комплексная система оценки и ранжирования узлов XBoard с защитой от различных видов мошенничества. Система основана на принципах PageRank и включает многоуровневую защиту от злоупотреблений.

**Основной узел:** `xdexboard.com` (домен) → `https://api.xdexboard.com` (API)

## Компоненты системы

### 1. NodeWeightManager (Клиент)
**Файл:** `shared/src/commonMain/kotlin/com/xrpchange/xboard/data/node/NodeWeightManager.kt`

**Функции:**
- Управление весами узлов по принципу PageRank
- Защита от дубликатов и спама в доверенных списках
- Отслеживание активности узлов (не просто пинг!)
- Регистрация и мониторинг взаимодействий с узлами
- Проверка взаимности доверия между узлами
- Валидация доверенных списков на двусторонность

**Ключевые особенности:**
- **PageRank-подобный алгоритм:** Вес узла зависит от весов узлов, которые его упоминают
- **Защита от дубликатов:** Максимум 1 упоминание одного узла от одного источника
- **Обнаружение спама:** Автоматическое обнаружение узлов с >80% дубликатов
- **Отслеживание активности:** Проверка реальной функциональности API, не просто доступности
- **Взаимность доверия:** Проверка двустороннего доверия между узлами
- **Защита от циклов:** Предотвращение бесконечных циклов упоминаний

### 2. NodeIpValidator (Клиент)
**Файл:** `shared/src/commonMain/kotlin/com/xrpchange/xboard/data/node/NodeIpValidator.kt`

**Функции:**
- Валидация IP-адресов узлов
- Защита от создания множественных узлов с одного IP
- Отслеживание подключений пользователей
- Выявление подозрительных IP-адресов

**Защита от мошенничества:**
- **Лимит узлов на IP:** Максимум 3 узла с одного IP-адреса
- **Счетчик подключений:** Отслеживание реальных подключений пользователей
- **Штрафы за подозрительность:** Автоматические штрафы за превышение лимитов

### 3. NodeSorter (Клиент)
**Файл:** `shared/src/commonMain/kotlin/com/xrpchange/xboard/data/node/NodeSorter.kt`

**Функции:**

- Учет множественных факторов при ранжировании
- Фильтрация узлов по минимальному рейтингу
- Статистика рейтингов

**Алгоритм сортировки:**
1. **Обязательные узлы** (is_required = true) - всегда первые
2. **Узлы по умолчанию** (is_default = true) - вторые
3. **Доверенные узлы** с высоким уровнем доверия
4. **Активные узлы** с большим количеством подключений
5. **Остальные узлы** по убыванию комплексного рейтинга

## Алгоритм работы системы

### 1. Инициализация
```
1. Загружается встроенный узел api.xdexboard.com
2. Создается NodeWeightManager и NodeIpValidator
3. Регистрируется основной узел в системе весов
```

### 2. Обнаружение узлов
```
1. Пингуется основной узел
2. Получается список доступных узлов
3. Для каждого узла:
   - Проверяется IP (защита от дубликатов)
   - Проверяется реальная активность (не просто пинг)
   - Рассчитывается вес и рейтинг
   - Регистрируется в системе весов
```

### 3. Проверка активности (не пинг!)
```
Для каждого узла проверяется:
1. API валют (20 баллов) - возвращает ли реальные данные
2. API стран (15 баллов) - работает ли корректно
3. API банков (15 баллов) - доступен ли
4. API эскроу токенов (25 баллов) - может ли создать токен
5. Базовое здоровье (5 баллов) - отвечает ли на запросы

Минимальный балл для доверия: 100 баллов
```

### 4. Система весов (PageRank)
```
Вес узла рассчитывается по формуле:
weight = Σ(weight_of_mentioning_node * decay_factor)

где:
- weight_of_mentioning_node - вес узла, который упоминает
- decay_factor - коэффициент затухания (0.9)
- Максимальный вес: 100
```

### 5. Защита от мошенничества
```
1. Дубликаты в доверенных списках:
   - Максимум 1 упоминание от одного источника
   - Обнаружение спама при >80% дубликатов

2. IP-мошенничество:
   - Максимум 3 узла с одного IP
   - Штрафы за превышение лимитов

3. Пустышки (неактивные узлы):
   - Проверка реальной функциональности
   - Минимум 5 подключений пользователей
   - Минимальный балл активности: 100

4. Одностороннее доверие (защита от бесконечных циклов):
   - Доверие должно быть взаимным
   - Если узел A доверяет узлу B, то узел B тоже должен доверять узлу A
   - Узлы с односторонним доверием исключаются из сети
   - Предотвращает создание бесконечных циклов упоминаний
```

### 6. Алгоритм взаимности доверия

```
Принцип работы:
1. Узел A предоставляет список доверенных узлов
2. Система проверяет каждый узел в списке
3. Для каждого узла B в списке A:
   - Проверяется, есть ли A в доверенном списке B
   - Если есть - доверие взаимное ✅
   - Если нет - одностороннее доверие ❌

Пример:
Узел A доверяет: [B, C, D]
Узел B доверяет: [A, C]     ← взаимное доверие A↔B ✅
Узел C доверяет: [B, D]     ← нет A в списке ❌
Узел D доверяет: [A, E]     ← взаимное доверие A↔D ✅

Результат: В сеть попадают только B и D, узел C исключается
```

### 7. Сортировка узлов
```
Приоритет сортировки:
1. Обязательные узлы (is_required = true)
2. Узлы по умолчанию (is_default = true)  
3. Доверенные узлы (is_trusted = true)
4. По уровню доверия (trust_level DESC)
5. По подключениям (user_connections DESC)
6. По приоритету (priority DESC)
7. По имени (name ASC)
```

### 8. Защита от бесконечных циклов

```
Проблема:
A → B → C → A (бесконечный цикл)

Решение через взаимность доверия:
1. A доверяет B, B доверяет A ✅
2. B доверяет C, C доверяет B ✅  
3. C доверяет A, A доверяет C ✅
4. Все связи взаимные - цикл безопасен

Если хотя бы одна связь односторонняя:
A → B ✅, B → C ✅, C → A ❌
Результат: узел C исключается, цикл разрывается
```

## Преимущества системы

### 1. Защита от мошенничества
- **Дубликаты:** Невозможно накрутить вес повторными упоминаниями
- **IP-мошенничество:** Ограничение количества узлов с одного IP
- **Пустышки:** Проверка реальной функциональности, не просто доступности
- **Спам:** Автоматическое обнаружение подозрительных узлов

### 2. Честное ранжирование
- **PageRank:** Вес зависит от качества упоминающих узлов
- **Реальная активность:** Учитывается функциональность, а не только доступность
- **Пользовательские подключения:** Учитывается реальное использование
- **Множественные факторы:** Комплексная оценка по многим критериям

### 3. Масштабируемость
- **Автоматическое обнаружение:** Система сама находит новые узлы
- **Самообновление:** Веса пересчитываются автоматически
- **Фильтрация:** Автоматическое исключение неактивных узлов
- **Производительность:** Индексы для быстрой сортировки

### 4. Прозрачность
- **Логирование:** Все действия записываются в лог
- **Статистика:** Доступна детальная статистика по узлам
- **Отчеты:** Подробные отчеты о активности узлов
- **Мониторинг:** Отслеживание состояния системы

## Принцип "Мы себе верим"

Система построена на принципе полного недоверия к внешним источникам и полагается только на собственные проверки и оценки.

### ✅ **Верим только себе:**
- **trust_level** - устанавливаем сами (0-10)
- **user_connections** - отслеживаем сами
- **trust_weight** - рассчитываем в клиенте на основе наших проверок активности
- **mentioned_by** - записываем в клиенте только наши открытия узлов

### ❌ **НЕ верим внешним источникам:**
- Не доверяем спискам доверенных узлов от других
- Не полагаемся на внешние рекомендации
- Не используем чужие оценки качества
- Не принимаем заявления о "хороших" узлах на веру

### 🛡️ **Защита от обмана:**
- **Все проверки** делаем сами (API endpoints, функциональность, скорость)
- **Все оценки** рассчитываем сами (PageRank, активность, штрафы)
- **Все данные** получаем из первых рук (прямые запросы к API)
- **Никому не верим** на слово

### 🏗️ **Архитектура доверия:**
- **Сервер:** хранит только наши контролируемые данные (`trust_level`, `user_connections`, `is_trusted`)
- **Клиент:** рассчитывает веса (`trust_weight`, `mentioned_by`) на основе собственных проверок
- **Никаких внешних источников** доверия в системе

**Основной узел:** `xdexboard.com` → `https://api.xdexboard.com` (Trust Level: 10)

Система готова к использованию и обеспечивает надежную защиту от различных видов злоупотреблений в сети узлов XBoard, включая защиту от бесконечных циклов доверия.
