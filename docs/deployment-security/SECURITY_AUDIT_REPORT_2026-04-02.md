## XBoard: отчёт по чек-листу безопасности деплоя (2026-04-02)

Этот отчёт фиксирует состояние прод‑окружения на `server@xrpchange.site` и известных сервисов XBoard на 2026‑04‑02, с опорой на чек‑лист из `SECURITY_AUDIT_CHECKLIST.md`.

---

### 1. Заполнение диска / ресурсоёмкие атаки

**1.1. Диск и директории**

- `df -h /` → корневой раздел `/`:
  - размер: ~247G;
  - использовано: ~150G (61%);
  - свободно: ~98G.
- Объёмы:
  - `/var/log` ≈ 35G;
  - `/var/mail` ≈ 892K.

**Вывод:** основную долю места занимает `/var/log`, почтовое хранилище по размеру сейчас не критично.

**1.2. Логи и очереди (Postfix / mail.log)**

- Postfix (через `postconf`):
  - `maximal_queue_lifetime = 10m`;
  - `bounce_queue_lifetime = 10m`;
  - `mailbox_size_limit = 102400` (100 КБ).
- Logrotate для `mail.log` (`/etc/logrotate.d/mail-xboard`) после донастройки:

  ```text
  /var/log/mail.log {
      size 10M
      daily
      rotate 7
      missingok
      notifempty
      compress
      delaycompress
      copytruncate
  }
  ```

  - Лог режется по размеру 10 МБ **и** ротации не реже раза в день, хранится до 7 сжатых копий.

**Оценка:**

- Очередь Postfix не может расти месяцами из‑за коротких `maximal_queue_lifetime`/`bounce_queue_lifetime`.
- Ограничение `mailbox_size_limit` = 100 КБ защищает отдельные ящики от разрастания.
- Для `mail.log` теперь есть и ограничение размера, и ротация/сжатие с историей.

**Статус:** частично покрыто.

- Сделано: лимиты очереди и ящиков, корректная ротация/сжатие `mail.log`.
- Осталось сделать: ревизия/жёсткая настройка logrotate для остальных логов (`/etc/logrotate.d/*`, особенно `nginx`, `php8.3-fpm`, `xboard-email`, `mysql-server`).

**1.3. IMAP‑хранилище (Dovecot)**

- Dovecot запущен (`dovecot/anvil`, `imap-login`, `imap` процессы активны).
- Для ящиков настроена регулярная очистка через `doveadm` (см. п.2).
- `mailbox_size_limit` ограничивает размер отдельного ящика 100 КБ.

**Статус:** защита от забивания диска письмами **есть**, но требует периодического контроля:

- лимиты на размер ящиков + hourly expunge/purge.

**1.4. Файлы и вложения (xboard-api)**

- На уровне сервера в этом обходе не проверялись конкретные каталоги `storage/app` / временные файлы чеков — требуются отдельные шаги по `xboard-api` (анализ `config/filesystems.php`, использования временных директорий, логики удаления чеков).

**Статус:** не проверено в этом проходе (отдельная задача по API).

---

### 2. SMTP / IMAP / почтовый слой

**2.1. Postfix ограничения**

`postconf` (выборочно):

- `maximal_queue_lifetime = 10m`
- `bounce_queue_lifetime = 10m`
- `mailbox_size_limit = 102400`
- `smtpd_client_connection_count_limit = 50`
- `smtpd_client_connection_rate_limit = 0`
- `smtpd_client_message_rate_limit = 0`
- `anvil_rate_time_unit = 60s`

**Оценка:**

- Лимит одновременных соединений с одного клиента (`smtpd_client_connection_count_limit = 50`) присутствует.
- Лимиты по **скорости** соединений и сообщений (`*_rate_limit`) пока не заданы (`0` = unlimited).

**Статус:** частично покрыто.

- Сделано: базовый лимит по количеству одновременных соединений.
- Рекомендуется: добавить разумные `smtpd_client_connection_rate_limit` / `smtpd_client_message_rate_limit` для защиты от флуд‑подключений.

**2.2. Dovecot / IMAP**

- Dovecot запущен, используются процессы `imap-login` и `imap`.
- В этом обходе не анализировались детально:
  - политика паролей;
  - лимиты сессий на IP;
  - наличие fail2ban‑правил по IMAP.

**Статус:** не проверено (нужен отдельный просмотр `dovecot.conf`, auth‑бэкенда и, при наличии, fail2ban‑конфигов).

**2.3. Email → чат (plain text)**

- Логика «email → чат» реализована в `xboard-api` / `xboard-client` и проверяется по коду/логам; в этом отчёте прямой runtime‑проверки на деплое не делалось.

**Статус:** не проверено в рамках этого SSH‑обхода (требуется код‑ревью и/или целевой тест сценария).

---

### 3. HTTP API (xboard-api, xboard-core)

- В этом обходе через SSH/сервер не проверялись:
  - конкретные rate limiting middleware в Laravel;
  - ограничения размеров payload / заголовков;
  - ACL/IDOR на уровне кода.
- В отдельной сессии (отдельный чат) уже были:
  - добавлены лимиты на сообщения чата в БД;
  - обсуждены и частично реализованы проверки для deal‑чатов и `deal_tag`.

**Статус:** частично покрыто на уровне кода, но **в контексте этого отчёта** статус: **не проверено** (нужно целевое тестирование по каждому подпункту чек‑листа).

---

### 4. Android‑клиент (xboard-client)

- В этом отчёте не проводилось отдельное тестирование APK на устройстве/эмуляторе:
  - не проверялись ANR под «грязными» письмами;
  - не тестировались deeplink‑цепочки на предмет открытия чужих сделок.
- По коду:
  - почта для чата идёт через API/IMAP, прямого SMTP из клиента наружу нет;
  - добавлены UI‑ограничения и вспомогательные функции для копирования/перевода сообщений.

**Статус:** не проверено на реальном деплое (это зона для отдельных ручных/автоматизированных тестов клиента).

---

### 5. Monero‑balance сервис (xboard-monero-balance)

- В этом обходе по SSH проверялась только почтовая/системная часть, без захода в конфиги balance‑сервиса.
- Авторизация по API‑ключу, IP‑границы и rate limiting для `/transfer`, `/balance` и других endpoints **не проверялись**.

**Статус:** не проверено (требуется целевой аудит конфигов balance‑сервиса и интеграции с core).

---

### 6. SSH / окружение сервера

- Проверен текущий `root`‑crontab:

  ```text
  0 3 1 * * /usr/local/bin/renew_cert.sh
  0 * * * * doveadm expunge -A mailbox  * BEFORE 1d && doveadm purge -A
  ```

  - Есть ежемесячное продление сертификатов.
  - Есть hourly‑очистка почтовых ящиков от писем старше 24 часов.

- В этом обходе **не проверялись**:
  - фактическая конфигурация `sshd` (только ключи или ещё пароли);
  - запрет root‑логина по SSH;
  - наличие/настройка fail2ban.

**Статус:** частично покрыто (cron‑задачи понятны и зафиксированы; SSH‑политика и fail2ban требуют отдельной проверки).

### Итог на 2026‑04‑02

1. **Очередь Postfix и размеры почтовых ящиков**: жёстко ограничены (`maximal_queue_lifetime`, `bounce_queue_lifetime`, `mailbox_size_limit`), настроена автоматическая очистка писем старше 24 часов через `doveadm`, `mail.log` ограничен по размеру.  
   → Риск забивания диска исключительно через SMTP/IMAP заметно снижен.

2. **Логи в целом**: `/var/log` уже занимает ~35G, но детальная ротация кроме `mail.log` в этом отчёте не анализировалась.  
   → Требуется отдельный проход по `logrotate` для nginx, php‑fpm, mysql, xboard‑email и пр.

3. **Postfix rate limiting**: есть лимит по числу одновременных соединений, но нет ограничений по скорости соединений/сообщений.  
   → Имеет смысл задать разумные `*_rate_limit` параметры.

4. **Остальные пункты чек‑листа (HTTP API, Android‑клиент, Monero‑balance, SSH‑политика)**: на уровне этого SSH‑обхода считаются **непроверенными** и требуют или отдельного кода‑аудита, или целевых тестов на деплое.

Этот отчёт можно дополнять по мере прохождения следующих шагов чек‑листа (например, добавляя разделы «Проверено 2026‑04‑05: logrotate», «Проверено 2026‑04‑10: SSH/fail2ban» и т.п.).
