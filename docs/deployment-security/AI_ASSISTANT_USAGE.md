## Использование AI‑ассистента (Cursor/ChatGPT и др.) в проектах XBoard

Этот документ фиксирует **правила работы с AI‑ассистентом** для всех репозиториев XBoard:

- `xboard-client`
- `xboard-api`
- `xboard-core`
- `xboard-monero-balance`

Цель — **не дать ассистенту случайно ослабить безопасность** (конфиги, ключи, доступы) и не «слить» чувствительные данные наружу.

---

### 1. Что ассистенту **нельзя показывать**

Ни при каких условиях не передавать в подсказках/вопросах/файлах:

- Файлы с секретами:
  - любые `.env*` (в том числе `.env.production`, `.env.sandbox` и т.п.);
  - приватные ключи (`*.pem`, `id_rsa`, `id_ed25519`, `*.key`);
  - дампы баз данных (`*.sql`, `*.dump`, `*.bak`);
  - `config/*.ini` или `config/*.php` с реальными паролями/ключами (Monero, balance‑service, почта и др.).
- Содержимое:
  - строк вида `PASSWORD=...`, `API_KEY=...`, `SECRET=...`, токенов для внешних сервисов;
  - приватных SSH‑конфигов (`~/.ssh/config` с хостами и юзерами).

Ассистенту можно описывать **структуру** (`есть .env с такими переменными`), но не показывать реальные значения.

---

### 2. Какие действия ассистент не должен выполнять сам

Ассистент **не должен** без явного запроса и отдельного ревью:

- Менять критичные системные конфиги:
  - `/etc/ssh/sshd_config`
  - `/etc/fail2ban/*`
  - `/etc/iptables/*` или правила фаервола.
- Менять доступы пользователей:
  - редактировать `/etc/passwd`, `/etc/group`, `/etc/sudoers`;
  - создавать/удалять системных пользователей без прямого запроса.
- Писать/изменять скрипты, которые:
  - автоматически деплоят на прод;
  - массово удаляют данные (`rm -rf`, `find … -delete`, любые `drop table`/`truncate` без миграций).

Любые такие изменения должны:

1. Быть явно согласованы в чате («сделай X в `sshd_config`»).
2. Сопровождаться понятным diff и ручной проверкой человеком.

---

### 3. Обязательная ручная проверка перед применением

Перед тем как:

- применять миграции БД;
- выкатывать изменения в:
  - `config/mail.php`, `postfix main.cf/master.cf`, `dovecot.conf`;
  - `nginx.conf`, `php-fpm` конфиги;
  - systemd‑юниты и cron;

нужно:

1. Просмотреть diff целиком (не только изменённые строки, но и контекст).
2. Проверить, что изменения не противоречат:
   - `POSTFIX_RELAY_AND_QUEUE.md`;
   - документации по Monero‑balance и его API;
   - общим требованиям из `SECURITY_AUDIT_CHECKLIST.md`.
3. При сомнениях — сначала задать ассистенту уточняющий вопрос, **а не применять вслепую**.

---

### 4. Что можно и нужно автоматизировать с помощью ассистента

Безопасные и полезные задачи для AI‑ассистента:

- Рефакторинг и навигация по коду:
  - поиск/объяснение участков кода;
  - предложенные улучшения без изменения конфигов/секретов.
- Документация:
  - генерация/структурирование `.md` файлов (как этот);
  - обновление чек‑листов и отчётов.
- Локальные проверки:
  - генерация SQL/миграций **без** реальных данных (с последующей ручной правкой);
  - предложения по внедрению rate limiting, логирования, валидации.

---

### 5. Связь с чек‑листом безопасности

В `SECURITY_AUDIT_CHECKLIST.md` добавить/учесть пункт:

- **AI‑assistant attack surface**:
  - Перед релизом убедиться, что:
    - в репозитории нет приватных ключей, дампов БД и прод `.env`;
    - `.gitignore` исключает все чувствительные файлы;
    - разработчики следуют правилам из `AI_ASSISTANT_USAGE.md`.

Этот файл считается частью обязательного набора документов по деплою и безопасности (`docs/deployment-security/*`).
