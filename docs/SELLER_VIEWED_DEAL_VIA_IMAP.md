# Уведомление покупателя «продавец зашёл в окно сделки» через IMAP/Maildir

**Цель:** когда продавец открывает экран «Сделка в процессе», покупатель должен об этом узнать. Пушей нет; используем ту же цепочку, что и для «Статус уведомления продавца» — IMAP/Maildir и опрос API.

## Текущая схема

- Покупатель шлёт сообщение продавцу → API кладёт письмо в **ящик продавца** (лот).
- Покупатель опрашивает `GET /exchange-lots/{lot}/deal-message-status` → API смотрит **ящик продавца** (Maildir по `wallet_address` лота) и возвращает `delivered`, `read`.
- Ящик покупателя в сделке — это `buyer_lot_email` на лоте (адрес ящика покупателя).

## Идея

1. **Событие «продавец открыл экран»**  
   При открытии экрана «Сделка в процессе» у продавца клиент вызывает новый эндпоинт, например:
   `POST /exchange-lots/{lot}/seller-viewed`  
   с эскроу-токеном продавца (проверка: запрос может делать только владелец лота).

2. **Запись в ящик покупателя**  
   API не шлёт письмо «наружу», а **записывает сообщение в Maildir ящика покупателя** (`buyer_lot_email`):
   - Находим ящик по `buyer_lot_email` (таблица `lot_mailboxes`: `local_part` + `domain` из адреса).
   - Кладём в его Maildir (в `new/`) одно письмо с фиксированным признаком, например:
     - Subject: `Deal event — Lot #123 — seller_viewed` (или заголовок `X-Message-Type: seller_viewed_deal`),
     - в теле или заголовке — timestamp (когда продавец зашёл).
   - Формат файла — обычное Maildir-письмо (как уже делаем для писем в ящик продавца), чтобы не ломать IMAP.

3. **Чтение при опросе статуса**  
   Ответ `GET /exchange-lots/{lot}/deal-message-status` расширяем:
   - Как сейчас: по ящику **продавца** считаем `delivered`, `read`.
   - Дополнительно: по ящику **покупателя** (`buyer_lot_email`) ищем последнее письмо с типом `seller_viewed_deal` (по Subject или `X-Message-Type`), берём его время и возвращаем в ответе, например:
     - `seller_viewed_at` (ISO 8601 или unix timestamp).

4. **Клиент покупателя**  
   На экране «Сделка в процессе» при уже существующем опросе `deal-message-status` использует новое поле `seller_viewed_at` и показывает текст вроде: «Продавец заходил в окно сделки 14:32» или «Продавец в окне сделки» (если нужна только метка времени).

## Детали API

### POST /exchange-lots/{lot}/seller-viewed

- **Авторизация:** эскроу-токен (как у `send-message`). Middleware проверяет, что запрос от владельца лота (сравнение mailbox email с ящиком лота по `wallet_address` + currency).
- **Ответ:** 200 OK (и при успешной записи в Maildir покупателя).
- **Действие:** записать в Maildir ящика `lot.buyer_lot_email` одно системное письмо с типом `seller_viewed_deal` и текущим временем.

### GET /exchange-lots/{lot}/deal-message-status

- **Ответ (расширение):** кроме `delivered`, `read` добавить:
  - `seller_viewed_at` (string|null) — ISO 8601 или null, если событий «продавец зашёл» нет.

Логика: по `lot.buyer_lot_email` вычислить путь Maildir (через `lot_mailboxes` или по разбору адреса), просканировать `new/` и `cur/` в поисках писем с признаком `seller_viewed_deal`, взять время последнего такого письма.

## Сервис (LotMailboxService)

- **writeSellerViewedToBuyerMailbox(string $buyerMailboxEmail, string $lotId): bool**  
  Найти ящик по `$buyerMailboxEmail` (например, разбор адреса → `local_part` + `domain` → путь Maildir). Создать один файл в `new/` в формате Maildir с Subject/заголовком, по которому потом находим событие. Вернуть true при успехе.

- **getSellerViewedAt(string $buyerMailboxEmail, string $lotId): ?string**  
  По тому же пути прочитать последнее письмо с типом `seller_viewed_deal`, вернуть его время (ISO 8601 или timestamp как строка) или null.

Либо оба метода принимают уже `$maildirPath`, если путь формируется в контроллере/выше.

## Клиент продавца

- При открытии экрана «Сделка в процессе (продавец)» один раз вызвать `POST .../seller-viewed` (если есть `lot.id` и авторизация продавца). Повторные вызовы при каждом открытии экрана — нормально (покупатель увидит последнее время захода).

## Итог

Всё идёт по той же «дороге»: IMAP/Maildir, без пушей. Покупатель узнаёт о заходе продавца при следующем опросе `deal-message-status`; в UI можно показывать «Продавец заходил в сделку в …» или «Продавец в окне сделки».
